## Logical Combinators

Multiple conditions can be assembled using logical AND (`&`), OR (`|`), and negation (`!`):

| Operator | Syntax | Precedence | Meaning |
| :--- | :--- | :--- | :--- |
| `!` / `not` | `!{p.condition}` or `!(...)` | Highest | Inverts truth value |
| `&` | `{p.c1} & {p.c2}` | Medium | True only if both conditions are true |
| `\|` | `{p.c1} \| {p.c2}` | Lowest | True if either condition is true |

### Operator Precedence & Grouping

Parentheses `( ... )` explicitly enforce evaluation order:

```text
findAll( p -> ( {p.tempC > 40} | {p.humidity > 80} ) & !{p.status == "STANDBY"} )
```

Without parentheses, `&` binds tighter than `|`:

```text
{p.a} | {p.b} & {p.c}   // Evaluates as: {p.a} | ( {p.b} & {p.c} )
```

### Negation Examples

## Set Membership: `in` and `not in`

Check whether a field matches any value in a discrete set of literals:

```text
{ <variable>.<field> in [ <val1>, <val2>, ... ] }
{ <variable>.<field> not in [ <val1>, <val2>, ... ] }
```

### Examples

```text
// Match any point in high alert states
findAll( p -> {p.status in ["WARN_HIGH_TEMP", "CRITICAL_PRESSURE", "EMERGENCY"]} )

// Exclude standard operational codes
findAll( p -> {p.errorCode not in [0, 200, 204]} )
```

Elements in the set can be numbers, strings, or booleans.

---

## Range Operator: `between ... and ...`

The `between` operator checks if a numerical or chronological field falls within an inclusive closed interval $[min, max]$.

```text
{ <variable>.<field> between <min> and <max> }
```

### Examples

```text
// Match comfort zone temperatures between 20.0 °C and 24.5 °C (inclusive)
findAll( p -> {p.tempC between 20.0 and 24.5} )

// Filter by ISO timestamp string boundaries
findAll( p -> {p.recordedAt between "2026-11-01" and "2026-11-08"} )
```

## Nullability & Presence Checks

Sensors may fail to transmit specific payload metrics when sensors disconnect, wires fray, or packets drop. TQL provides dedicated presence operators to filter on data availability:

### Checking for Null / Non-Null

- `{p.field is null}`: Evaluates to `true` if the field is `null` or `undefined`.
- `{p.field is not null}`: Evaluates to `true` if the field holds a concrete value.

```text
// Find points where the external barometer failed to report a value
findAll( p -> {p.barometer.pressure is null} )

// Only process records that have valid battery readings
findAll( p -> {p.battery.voltage is not null} )
```

### Checking for Property Presence / Absence

- `{p.field exists}` or `{p.field is present}`: True if property exists on the record.
- `{p.field missing}` or `{p.field is missing}`: True if property does not exist.

```text
// Detect points containing optional GPS coordinates
findAll( p -> {p.location.latitude exists} )
```

## String Pattern Matching

TelemetryQL provides built-in operators for string inspection, prefixes, suffixes, and regular expressions:

| Operator | Example | Evaluates To |
| :--- | :--- | :--- |
| `contains` | `{p.msg contains "error"}` | `String(p.msg).includes("error")` |
| `not contains` | `{p.msg not contains "debug"}` | `!String(p.msg).includes("debug")` |
| `startsWith` | `{p.device startsWith "ESP32"}` | `String(p.device).startsWith("ESP32")` |
| `endsWith` | `{p.file endsWith ".csv"}` | `String(p.file).endsWith(".csv")` |
| `=~` (regex match) | `{p.serial =~ "^AYP-[0-9]{6}$"}` | `RegExp.test(p.serial)` |
| `!~` (regex non-match) | `{p.logLine !~ "HEALTHY\|HEARTBEAT"}` | `!RegExp.test(p.logLine)` |

### Examples

```text
// Isolate firmware versions from the beta branch
findAll( p -> {p.firmware startsWith "v3.0.0-beta"} )

// Detect error log lines matching regex
findAll( p -> {p.log.message =~ "(?i)fail(ure\|ed)?"} )
```
