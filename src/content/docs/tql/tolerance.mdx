Physical hardware sensors rarely emit completely steady values. Temperature probes experience subtle thermoelectric variations, humidity sensors drift with ambient convection, and Analog-to-Digital Converters (ADCs) introduce quantization noise.

Attempting to match sensor values with exact equality (`{temperature == 22.0}`) will cause queries to miss valid readings that fluctuate by hundredths or tenths of a degree (e.g. `22.004 °C`).

TelemetryQL solves this fundamental IoT challenge with **first-class tolerance operators**.

---

## Absolute Delta Operator (`~<delta>~=`)

The absolute delta operator evaluates to `true` if the field value falls within a fixed interval centered on the target value.

```text
{ <field> ~<delta>~= <center> }
```

### Formula

```text
Matching Range = [center - delta, center + delta]
center - delta <= field <= center + delta
```

### Example

Consider matching relative humidity within $\pm 0.5\%$ of a target $52\%$:

```text
findAll( p -> {relHumidity ~0.5~= 52} )
```

- **Delta:** `0.5`
- **Target Center:** `52`
- **Matching Interval:** `51.5` to `52.5`

Any telemetry point with `relHumidity` between `51.5` and `52.5` (inclusive) evaluates to `true`.

---

## Percentage Tolerance Operator (`~<delta>%~=`)

When operating across wide dynamic ranges (such as mains electrical voltage, engine RPM, or atmospheric pressure), a proportional percentage deviation is often preferred over an absolute offset.

TelemetryQL provides the percentage tolerance operator (`~<delta>%~=`):

```text
{ <field> ~<delta>%~= <center> }
```

### Formula

```text
absoluteDelta = |center * (deltaPercent / 100)|
Matching Range = [center - absoluteDelta, center + absoluteDelta]
```

### Example

Consider validating that a mains AC voltage sensor stays within ±5% of 220 V:

```text
findAll( p -> {voltage ~5%~= 220} )
```

- **Target Center:** `220`
- **Percentage:** `5%` (220 * 0.05 = 11.0 V)
- **Matching Interval:** `209.0` to `231.0`

## Dynamic Setpoint Fields

Telemetry points frequently record both an **actual measured value** and a **dynamic setpoint** generated by a thermostat or PID controller loop.

TQL allows the center operand to reference another field on the same point:

<Tabs>
  <TabItem label="Absolute Dynamic Tolerance">
    ```text
    // Matches points where currentTemp is within 1.5 °C of targetTemp
    findAll( p -> {currentTemp ~1.5~= targetTemp} )
    ```
  </TabItem>
  <TabItem label="Percentage Dynamic Tolerance">
    ```text
    // Matches points where measuredRPM is within 3% of demandedRPM
    findAll( p -> {measuredRPM ~3%~= demandedRPM} )
    ```
  </TabItem>
</Tabs>

## Non-Numeric & Missing Value Protection

Tolerance operators evaluate physical measurements and require numeric inputs. If either the target field or the center reference:
- Is `null` or `undefined`
- Is a non-numeric string or boolean
- Evaluates to `NaN` or `Infinity`

The tolerance condition automatically and safely evaluates to `false`. It will never produce unexpected runtime exceptions.
